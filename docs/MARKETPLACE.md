# Marketplace listing

Everything below is the source of truth for the GitHub Marketplace listing and
the plan names the webhook maps to tiers (`worker/accounts.py: PLAN_MAP`).

## Plans

| Plan | Price | Marketplace plan name | Tier | What you get |
|---|---|---|---|---|
| Free | $0 | `Free` | `free` | Public + private repos, docs regenerated on every push to the default branch, generated by a self-hosted open-weights model. Best-effort queue. |
| Pro | $9 / month per account (recommended; set in the listing) | `Pro` | `pro` | Everything in Free, plus: priority queue, and jobs automatically routed to Claude (Anthropic) when the local queue is deep or the local model is unhealthy, capped by the operator's daily spend limit. |

Plan names in the listing must match `PLAN_MAP` exactly (`Free`, `Pro`); any unknown
name maps to `free`. Cancellation events downgrade to `free` immediately.

**Why $9:** the marginal cost of a Pro job that spills is bounded by the daily cap
(`DAILY_USD_CAP`). One spilled mid-size repo at claude-opus-5 / effort medium is on the
order of 30–60k input + 5k output tokens ≈ $0.30–$0.45. Ten regenerations a month is
under $5; $9 leaves margin. Revisit after the first invoices.

## Listing copy

**Name:** docbot

**Tagline (≤ 80 chars):** Docs that stay current: README, module guides and API reference on every push.

**Description:**

docbot keeps your repository documentation in sync with your code. Install it, and on
every push to your default branch it reads your file tree, public signatures and existing
README, then opens (or updates) a single pull request on the `docs/auto` branch containing:

- a README with real install/usage commands taken from your code,
- one guide per top-level module — purpose, key components, entry points, gotchas,
- an API reference of your public surface.

Nothing is merged automatically: you review the PR like any other. Re-running never
creates duplicate PRs — the same branch is force-pushed and the same PR updated.

Only the files needed are read; vendored, generated and binary paths are skipped, and
repositories over the size cap are refused rather than partially documented.

**Permissions requested and why:**
- Contents (read & write): clone the repo, push the `docs/auto` branch.
- Pull requests (read & write): open/update the docs PR.
- Metadata (read): required by GitHub for all apps.

**Categories:** Code review · Continuous integration · Documentation (pick what GitHub offers)

**Support:** https://github.com/joshebel/docbot/issues

**Privacy:** Source is cloned to the worker for the duration of a job and deleted after.
Free-tier generation runs on operator-hosted infrastructure. Pro-tier jobs may be sent to
Anthropic's API under their data-handling terms. No source is retained after the PR is opened.

## Publishing checklist (GitHub UI — operator must do these)

1. App settings → **Public page**: make the App public ("Any account" install option).
2. App settings → **Marketplace** → *List in Marketplace* → creates a **draft** listing.
3. Fill listing from the copy above; add a logo (≥ 200×200) and one screenshot of a docs PR.
4. **Plans & pricing** → add `Free` ($0) and `Pro` ($9/mo, per-account). Paid plans require:
   - a verified publisher (GitHub identity verification), and
   - accepting the **GitHub Marketplace Developer Agreement**, and
   - payout details in GitHub's Stripe-backed flow.
5. Webhook: set the App's webhook URL to the public receiver (`/`), `Active` on, and the same
   secret as `GH_WEBHOOK_SECRET`. Subscribe to: **Installation**, **Installation repositories**,
   **Push**, **Marketplace purchase**.
6. Submit for review. GitHub requires ≥ 100 installs *or* a verified publisher for a listing
   with paid plans; free-only listings can publish immediately after review.

The worker side needs nothing else: `python -m worker webhook` (behind a tunnel/reverse
proxy) and `python -m worker serve`.
